# 素材上传 + 在线看板 · 使用指南

给第一次拿到这套东西的人看。跟着走一遍,大约十分钟能出第一个可以发给别人的看板链接。

它解决的问题:**你有一堆视频要给别人看,但微信传不动、共享盘要开权限。**
这套流程把素材传到公司对象存储,生成一个网页,链接发出去谁都能打开,能筛选、能对比播放。

```
本地文件夹  ──上传──>  对象存储  ──发布──>  一个网页链接
                          │
                     顺便生成一份 URL 清单 csv
```

---

## 一、第一次安装

### 1. 确认有 Python

```bash
python --version
```

需要 3.8 以上。没有就去 python.org 装,安装时**记得勾选 Add Python to PATH**。

### 2. 装两个依赖

```bash
pip install boto3 openpyxl
```

`boto3` 是必须的。`openpyxl` 只有读写 Excel 清单时才用到,先装上省事。

### 3. 想好两个值

安装脚本会问你要这两个,**先想清楚再动手**:

| 要填的 | 什么意思 | 例子 |
|---|---|---|
| **本地根目录** | 素材放在哪。它下面每个子文件夹算一个批次 | `D:/我的项目/upload_content` |
| **线上前缀** | 你在桶里的文件夹名 | `zhangsan_data` |

> **前缀千万别和同事重名。** 同名会直接覆盖对方的文件,没有任何提示。
> 建议用「名字缩写 + 项目名」,比如 `zhangsan_blender`、`lisi_shortvideo`。

### 4. 跑安装

在技能目录里执行:

```bash
python scripts/setup.py --root "D:/我的项目/upload_content" --prefix "zhangsan_data"
```

不带参数直接跑 `python scripts/setup.py` 也行,它会一个个问你。

正常会看到:

```
拷贝主程序:
  auto_upload_to_blob.py
  dashboard_server.py
  视频数据看板v3.html

配置已写入 D:\我的项目\blob_config.json

连通性自检:
  [√] 连通,zhangsan_data 现在还是空的(第一次用就该是空的)
```

**看到 `[×] 连不上` 就停下来**,先解决网络再往下走。通常是没连内网/办公网。

装完你的目录长这样,**以后所有命令都在「工作目录」这一层跑**:

```
D:/我的项目/                    ← 工作目录,命令在这里跑
  blob_config.json              ← 配置,以后改这个
  auto_upload_to_blob.py
  dashboard_server.py
  视频数据看板v3.html
  upload_content/               ← 本地根目录,素材放这里
```

## 二、素材怎么摆

**下面一层是批次,再下面一层是角色**,本地什么结构,线上就是什么结构:

```
upload_content/
  0806/                       ← 批次,通常用日期
    source_video/    a.mp4    ← 原视频
    target_video/    a.mp4    ← 生成后的视频
    reference_image/ a.png    ← 参考图
    prompt_list.xlsx          ← 提示词清单,可选
  0812/
    source_video/    b.mp4
```

传上去以后,`0806/source_video/a.mp4` 对应的地址就是:

```
https://blobstore.example.com/bucket-b/zhangsan_data/0806/source_video/a.mp4
                                  └─ 桶 ─┘        └─ 你的前缀 ─┘ └─ 本地相对路径 ─┘
```

**关于命名**:角色目录名里带 `source` / `target` / `reference` 时,看板会自动识别成对比三栏。文件名里的编号(`_01`、`_l3`)用来把三者配成一组。名字不规范也能传,只是看板认不出角色,会当成散装文件列出来。

只有一种素材(比如只有原视频)完全没问题,看板里用「图墙」视图看更合适。

## 三、第一次上传

### 先空跑,看看会传什么

```bash
python auto_upload_to_blob.py --once --dry-run
```

这一步不会真传,只列清单。确认路径和数量对得上再继续。

### 真传

```bash
python auto_upload_to_blob.py --once
```

会看到进度条,每个文件传完立刻核对线上大小,对不上会报 `[BAD]`。

传完自动在批次目录下生成 `0806/0806_blob_urls.csv`,四列:文件名 / 相对路径 / 大小 / 线上 URL。这份表可以直接发给别人。

> **刚拷完文件立刻跑,提示「没有需要上传的」?**
> 这是防半截保护:文件最后修改时间不足 5 秒的会跳过,免得把还在写的 mp4 传上去。等几秒重跑就行。

## 四、看板怎么打开

三种方式,按「谁需要看」来选:

### 要发给别人 → 发布到线上

```bash
python auto_upload_to_blob.py --publish
```

打印出来的那个链接,发给谁都能打开,不用装任何东西。

**每次新增素材后都要重跑一次 `--publish`**,否则线上看到的还是旧内容。

### 只有自己看,或同网段的同事看 → 本地起服务

```bash
python dashboard_server.py
```

浏览器打开 http://localhost:8765 。启动时会打印你的内网 IP,同网段的人用那个地址也能看。

### 什么都不想装 → 直接双击 html

功能受限,得手动点「📁 选择文件夹」把素材目录选进去。应急用。

---

## 五、日常最省事的用法

开一个窗口挂着监听:

```bash
python auto_upload_to_blob.py --watch
```

之后**把文件丢进批次目录就完事了**,剩下的全自动:每 10 秒扫一次 → 上传 → 核对 → 更新清单 csv → 刷新线上索引和页面。

只要 watch 开着,加了新素材网页就会自动更新,**不用手动跑 `--publish`**。

改了脚本也不用重启它:每轮会检查自身源码有没有变,变了就原地重启加载新代码。

## 六、命令速查

```bash
# 上传
python auto_upload_to_blob.py --once              # 传一次就退出
python auto_upload_to_blob.py --once --dry-run    # 只看不传
python auto_upload_to_blob.py --once --dir 0806   # 只处理某个批次
python auto_upload_to_blob.py --watch             # 常驻监听

# 修复与重建
python auto_upload_to_blob.py --repair            # 核对线上大小,只重传损坏/缺失的
python auto_upload_to_blob.py --write-urls        # 不上传,只重新生成 URL 清单
python auto_upload_to_blob.py --publish           # 不扫素材,只重新发布页面和索引
python auto_upload_to_blob.py --once --fill-xlsx  # 把 URL 回填进批次的 xlsx

# 排查
python auto_upload_to_blob.py --show-config       # 看当前生效的配置
python dashboard_server.py 9000                   # 换个端口起看板
```

完整参数表见 [reference.md](reference.md)。

## 七、改配置

**只改 `blob_config.json`,不要改 .py。** 换个项目通常只需要动前两项:

```json
{
  "local_root": "D:/我的项目/upload_content",
  "key_prefix": "zhangsan_data",
  "bucket": "bucket-b",
  "endpoint": "https://blobstore.example.com",
  "public_host": "https://blobstore.example.com",
  "service_header": "grpc_onlineEarningGenRpcService"
}
```

只想临时换一次、不想改文件,用命令行覆盖:

```bash
python auto_upload_to_blob.py --once --prefix zhangsan_test
```

## 八、出问题先看这里

**传上去的视频播不了 / 下载提示文件不完整**

boto3 新版本默认给上传加 CRC32 校验,body 以 `aws-chunked` 分块发送,而网关不解这层编码,会把分块头当内容存进去。脚本里已经关掉了。怀疑还有历史坏文件就跑:

```bash
python auto_upload_to_blob.py --repair
```

**明明有新文件,却说「没有需要上传的」**

文件刚写完不到 5 秒,防半截保护挡住了。等几秒重跑。这是正常保护,不是 bug。

**素材一直传不上去**

检查是不是命中了跳过规则。这些不传:`~$*`、`.*`、`*.tmp`、`*.part`、`*.crdownload`、`*.lock`;这些目录不进:`frames`、`_logs`、`_build`、`__pycache__`、`.git`、`_archive`;后缀不在 `.mp4 .mov .webm .png .jpg .jpeg .webp .csv .xlsx .json .txt .md` 里的也不传。

**线上看板打不开,或内容是旧的**

没发布。跑一次 `--publish`。

**看板下拉显示「读取失败」**

括号里写着真实原因。`HTTP 404` 说明当前既不是通过 `dashboard_server.py` 打开的、同目录也没有索引文件。改用 http://localhost:8765 ,或者跑一次 `--publish` 后从线上地址打开。

**下拉是空的 / 数据不更新**

多半是改代码之前启动的老进程还跑着。查一下重启:

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match "auto_upload|dashboard_server" } |
  Select-Object ProcessId, CreationDate, CommandLine
```

**本地删了文件,线上还在**

脚本是只增不删的,记账本只记「传过什么」。要清线上得手动删对象。这是有意为之——一刀切的同步删除会把那些本地已经没有副本、但线上还需要的历史文件一起抹掉。

**换了目录后所有文件重传一遍**

上传记账本 `.blob_upload_state.json` 跟着 `local_root` 走,换根目录等于换了一本账。加 `--verify-remote` 可以跳过线上已经存在且大小一致的。

## 九、几个容易搞混的地方

**两种「清单」不是一回事**

`<批次>_blob_urls.csv` 是**上传记录**,四列,纯粹记「这批传了什么、地址是多少」,自动生成。

`dashboard_index.json` 是**页面的目录索引**,告诉托管在线上的网页「有哪些文件、哪些清单能读」。看板托管出去以后没有后端接口可用,全靠这份索引自描述。**不重跑 `--publish` 它就不会更新**,这是「网页看不到新素材」最常见的原因。

**`.blob_upload_state.json` 别删**

上传记账本,靠它判断哪些文件传过。删了会全量重传一遍。

**看板有两种视图**

「对比卡片」一行显示参考图 + 原视频 + 目标视频横排,适合逐条核对提示词、同步播放对比。

「图墙」只显示一种素材的缩略图,六列平铺,鼠标悬停自动播放,适合快速过一遍找废片。只有一种素材的批次用图墙看舒服得多——卡片模式下另外两栏是空的。

切换在筛选栏最左边。

## 十、部署给下一个人

把整个技能目录拷给他,让他从第一步开始走一遍。

**从 `scripts/` 拷正本**,不要从某个同事的工作目录二次拷贝——那里的文件可能已经被改过了。
