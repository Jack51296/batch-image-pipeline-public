## 1. 环境与账号（每次开工先做）

1. **启动调试 Chrome**（本机 PowerShell；Chrome 需全部关闭再执行）：

   ```powershell
   Start-Process "C:\Program Files\Google\Chrome\Application\chrome.exe" -ArgumentList `
     '--remote-debugging-port=9222', "--user-data-dir=$env:USERPROFILE\chrome-kling-debug", `
     'https://devbox.example.com/?folder=/mnt/kfs/bob'
   ```

2. 在弹出的 Chrome 里**手动完成 SSO 登录**（双因素）。登录后是网页版 VS Code。
3. 页面上按 **Ctrl+`** 打开终端（自动化工具也要求终端已打开）。
4. 远端固定事实（换机器需重新确认）：
   - 代码目录：`/mnt/kfs/bob/光影光效2/`（含 batches/、skills/、prompts.json）
   - 原图库：`/mnt/kfs/bob/光影光效/2608**-…/`
   - 系统 `python3` = 3.6.8，跑清单/出图/交付没问题；
     **对齐必须用** `/root/miniconda3/envs/comfyui-v4.0/bin/python`（3.10 + cv2 4.11）
   - 出图 API：gpt-image-2 edits 模式，并发 5，限速约 8 次/分钟，已有图自动跳过
   - 重复数据记录（0907 md5 实测，明细 CSV 在代码目录）：
     `dup_groups_4档.csv` 自有 6 个批次 91 组 183 张；
     `dup_groups_P0.csv` carol 光影光效P0 17 个 4-目录 239 组 487 张（跨批次 225 组，
     常见"同图不同光效标签"，如 暖光⇔夕阳光、硬光⇔太阳光）

> KFS 安全习惯：`/mnt/kfs` 是 Ceph 共享存储。对陌生大目录做 find/du 等递归扫描前，
> 先 `getfattr -n ceph.dir.rfiles <目录>` 看文件数，超过 100 万先停下确认。

> **文件操作红线：本机文件可整理修改；非本机内容只能复制，不得原地修改或删除。**
> 网盘共享、开发机上他人目录（如 `/mnt/kfs/dave/…`）、Kim 收件原件一律只读；
> 要改就先复制到自己的工作区（如 `/mnt/kfs/bob/光影光效2/`）再改。

## 2. 场景 A：全量跑批（现有 0818 / 0819 / 0819b）

```bash
cd /mnt/kfs/bob/光影光效2

# ① 确认 work_dir。测试后遗留指向 test_work，正式跑改成 prod_work：
sed -i 's|光影光效2/test_work|光影光效2/prod_work|g' \
  batches/index.json batches/0818/config.json batches/0819/config.json batches/0819b/config.json
mkdir -p prod_work

# ② 生成清单（约半分钟；行数 ≈ 图数×3 即成功）
python3 -u build_jsonl_lighting.py --batch all
wc -l batches/*/Prompt_with_images.jsonl

# ②b 去重过滤（必做！剔除跨批次内容重复的图，防止重复跑）
#    自动合并代码目录下所有 dup_skip_list*.txt（现有：4档 92 条 + P0 248 条）
#    范围只限 4-… 档目录：脚本内置保险，3.5 档等其他档位的行一律保留不剔
for b in 0818 0819 0819b; do
  python3 filter_dup_jsonl.py batches/$b/Prompt_with_images.jsonl \
    batches/$b/Prompt_with_images.dedup.jsonl
done
# 0907 实测：0818 剔 18 行 / 0819 剔 102 行 / 0819b 剔 108 行（=76 张重复图 ×3 轮）

# ③ 出图+追色（用 dedup 后的清单！限速下约 9 小时/批 → 挂后台）
nohup python3 -u gen_image_lighting.py --batch 0818 \
  --input-jsonl batches/0818/Prompt_with_images.dedup.jsonl > log_0818.txt 2>&1 &
tail -f log_0818.txt        # 随时看进度；断了重跑同命令自动续
# 0819、0819b 同理逐批跑

# ④ 对齐（换 python！每批一条）
/root/miniconda3/envs/comfyui-v4.0/bin/python -u skills/lighting-destyle-align/align_batch.py \
  --csv prod_work/Prompt_with_images_0818.csv --workers 4

# ⑤（可选）人工审核：文件树右键下载 *_align_out → 本机开 review/index.html 审核
#    → decisions.json 拖回 _align_out → --finalize 生成 aligned_for_label.csv

# ⑥ 交付表 + 校验（看到 结论：通过 才算完）
python3 -u make_lighting_delivery_csv.py --batch all --verify
```

结尾把 `prod_work/*-qt-round1/` 与 `batches/*/*_光影_final.csv` 拷到网盘
`\\10.0.0.11\share\frank\光影图生图\<日期>\`（参照已有 0828 的组织方式）。

## 3. 场景 B：新增批次跑量（新原图目录）

1. 原图上传/放置到 `/mnt/kfs/bob/光影光效/<新批次目录>/`
   （沿用现有组织：按 `强度-张数` 分子文件夹，文件名 `光效名-强度-横竖屏-序号.jpg`）。
2. **核对提示词**：新批次涉及的光效必须在 `提示词总表-通过清单.csv` 里（进度=通过）。
   总表刚更新过就先跑 `python scripts\filter_pass.py` 刷新清单；
   若有新光效，需同步更新代码目录的 `prompts.json` 再进行下一步。
3. 注册批次：在 `batches/` 下新建 `<新id>/config.json`，并在 `batches/index.json` 加同名条目。
   两处内容一致，照抄 0818 的字段改这些值：

   ```json
   {
     "id": "<新id>",
     "image_root":     "/mnt/kfs/bob/光影光效/<新批次目录>",
     "kml_image_root": "/mnt/kfs/bob/光影光效/<新批次目录>",
     "local_image_root": "source_images/<新id>",
     "delivery_root":  "<新批次目录名>",
     "source_dir":     "<新批次目录名>",
     "output_rel_prefix": "<新批次目录名>-qt-round1",
     "work_dir": "/mnt/kfs/bob/光影光效2/prod_work",
     "jsonl": "batches/<新id>/Prompt_with_images.jsonl",
     "pipeline_csv": "Prompt_with_images_<新id>.csv",
     "delivery_csv": "batches/<新id>/<新id>_光影_final.csv"
   }
   ```

4. **查重并更新跳过清单**（新批次数据可能与旧批次内容重复）：
   照抄 `make_dup_lists.py`（或 `make_dup_lists_p0.py`）改 BASE 后跑一遍 →
   `gen_skip_from_csv.py` 生成新的 `dup_skip_list_<来源>.txt` 放代码目录。
   过滤脚本按"路径最后 3 段"匹配，原图整目录复制过来也能命中。
5. 之后与场景 A 相同：`build_jsonl_lighting.py --batch <新id>` → **②b 去重过滤** →
   先按场景 C 抽 1 张验证 → `gen_image_lighting.py --batch <新id> --input-jsonl …dedup.jsonl`
   → 对齐 → 交付表。

## 6. 坑速查（0907 实测）

| 现象 | 原因 | 处理 |
|---|---|---|
| 出图结束报 `shutdown() … 'cancel_futures'` | Python 3.6 兼容问题，发生在完工后的清理 | 无害，忽略 |
| 对齐报 `SyntaxError: future feature annotations` | 用了系统 python3(3.6) | 换 comfyui-v4.0 环境 python |
| `skills/lighting-destyle-align` 不存在 | 网盘代码包缺该 skill | 跑 `kml_upload_align_skill.py` 从本包补传 |
| `requirements-batch.txt` 装不上 | 要求 cv2≥4.8，py3.6 装不了 | 不用装，comfyui-v4.0 已满足 |
| 出图全被"跳过" | work_dir 里已有同名产物 | 换新 work_dir 或确认就是要续跑 |
| JSONL 行数为 0 | config 里 image_root 路径不对 | `ls` 逐级核对原图目录 |
| 同一张图被跑了多遍 | 出图没走去重清单 | 必做 ②b：`filter_dup_jsonl.py` 后用 `--input-jsonl …dedup.jsonl` |
| 过滤剔除 0 行但明知有重复 | 跳过清单没覆盖该数据来源 | 按场景 B 第 4 步为新来源生成 `dup_skip_list_*.txt` |
| 9222 连不上 / 页面要登录 | 调试 Chrome 没起 / SSO 过期 | 重做第 1 节两步 |
