# 批量跑图 实操步骤（0908 版，带原理串讲）

> 目标：你自己在 KML 开发机上一步步把一个批次从"原图"跑成"可交付成品"。
> 每步都按 **原理 → 在哪操作 → 敲什么 → 成功标志** 写。
> 当前真实进度（可直接接着练）：**0815 已跑完出图**；**0814 出图到 46% 被暂停**，
> 你从第 6 步"恢复跑量"开始就是真实操作，前面几步用只读命令复盘验证即可。

---

## 全流程一张图（顺序原理）

```text
原图目录          注册批次           任务清单            去重过滤
/光影光效/2608xx → batches/<id>/  → Prompt_with_images → .4dedup.jsonl
                   config.json      .jsonl（图×3轮）      （剔除重复图）
                                                            ↓
交付CSV      ←   几何对齐      ←   出图+追色（最耗时，挂后台）
final.csv        align_batch       gen_image_lighting
   ↓
复制到成品库 chatgpt-ketu/光照/
```

为什么是这个顺序：
- **先注册再建清单**：清单脚本要从 config.json 读"原图在哪、输出到哪"。
- **先去重再出图**：出图按清单逐行调 API（约 8 次/分钟），重复图剔在清单阶段最省钱。
- **先出图再对齐**：对齐是把"生成图"和"原图"做几何配准，没有生成图就没得对。
- **最后交付表**：交付 CSV 要汇总原图路径 + 生成图路径 + 对齐结果，所以放最后。

## 第 1 步 确认原图与注册批次

- **原理**：每个批次一个 id（如 0814），`batches/<id>/config.json` 记录原图目录
  （image_root）、输出目录（work_dir=prod_work）、交付名等；`batches/index.json`
  是所有批次的总登记表。脚本全靠它找路径。
- **敲什么**（复盘验证，只读）：

  ```bash

  python3 -c "import json;d=json.load(open('batches/0814/config.json'));print(d['image_root']);print(d['work_dir'])"
  ls "$(python3 -c "import json;print(json.load(open('batches/0814/config.json'))['image_root'])")" | head
  ```

- **成功标志**：image_root 指向 `/mnt/kfs/bob/光影光效/260814-…-5133`，
  最后一条 ls 能看到 `4-1707张`、`3.5-5133张` 之类的目录。
- **新批次才需要做的**：照抄 0818 的 config.json 改字段值 + 在 index.json 加同名条目
  （参考 `D:\TP\skill\SKILL.md` 场景 B 第 3 步）。0814/0815 我已注册好。

## 第 2 步 生成任务清单 JSONL

- **原理**：清单是出图的"待办列表"，**每张原图 3 行**（r1/r2/r3 三轮，同一提示词跑
  3 次取不同随机结果），每行含 id、原图路径、提示词。
- **敲什么**：

  ```bash
  python3 -u build_jsonl_lighting.py --batch 0814
  wc -l batches/0814/Prompt_with_images.jsonl
  ```

- **成功标志**：行数 ≈ 4-档图数 × 3（0814 全量清单里 4-档部分是 5118 行）。
- **已做**：0814/0815 的清单我已生成，直接 `wc -l` 验证即可。

## 第 3 步 去重过滤（出图前必做）

- **原理**：不同批次间存在内容完全相同的图（md5 相同、只是文件名/光效标签不同）。
  `filter_dup_jsonl.py` 读代码目录里所有 `dup_skip_list*.txt`（重复图记录），
  把清单里命中的行剔掉，**只作用于 4-… 档目录**，3.5 档等一律保留。
- **敲什么**：

  ```bash
  python3 filter_dup_jsonl.py batches/0814/Prompt_with_images.jsonl \
    batches/0814/Prompt_with_images.4dedup.jsonl
  ```

- **成功标志**：打印 `保留 xxxx 行，剔除 xx 行` 和 `FILTER_DONE`。
  （0814 实际：保留 5097、剔除 21；0815：保留 855、剔除 18。）
- **注意**：按你 0908 的决定，与成品库（0818/0819 已跑完成品）内容重复的 27 张
  **暂不剔除**，清单 `overlap_done_batches.txt` 只存档备查。

## 第 4 步 单图验证（放量前保险丝）

- **原理**：用 1 张图（3 行）把"出图→对齐→交付表"整链路走一遍，几分钟内暴露
  路径错、环境错等问题，避免挂了 9 小时后才发现白跑。
- **敲什么**：

  ```bash
  grep '某图名前缀-r' batches/0814/Prompt_with_images.4dedup.jsonl > test_one.jsonl
  wc -l test_one.jsonl        # 应为 3
  python3 -u gen_image_lighting.py --batch 0814 --input-jsonl test_one.jsonl 2>&1 | tee test_log.txt
  ```

- **成功标志**：进度条 3/3 100%；`prod_work/260814-…-qt-round1/` 里出现该图的
  `-r1/r2/r3.png` 和 `_colormatched.png` 共 6 个文件。
- **已做**：两个批次我都验证过，跳过即可。

## 第 5 步 正式出图（最耗时，挂后台）

- **原理**：逐行调 gpt-image-2 图生图接口（并发 5、限速约 8 次/分钟），每行产出
  `{id}.png`（生成图）和 `{id}_colormatched.png`（向原图追色版）。
  `nohup … &` 让它在后台跑、关网页也不断；**断点续跑安全**——输出文件已存在的行
  自动跳过，中断后重跑同一条命令即可接着跑。
- **敲什么**（0814 当时的启动命令，现在不要重复执行，见第 6 步）：

  ```bash
  nohup python3 -u gen_image_lighting.py --batch 0814 \
    --input-jsonl batches/0814/Prompt_with_images.4dedup.jsonl > log_0814.txt 2>&1 &
  ```

- **监控**：

  ```bash
  tail -2 log_0814.txt                       # 进度条：已完成/总数、速度、剩余时间
  ls prod_work/260814-*-qt-round1 | wc -l    # 产出文件数（≈完成行数×2）
  ```

- **成功标志**：进度到 100%；结尾报 `TypeError: shutdown() … cancel_futures` 是
  Python3.6 的无害收尾错误，不用管。

## 第 6 步（★你现在从这里开始实操）恢复被暂停的 0814

- **原理**：我下午用 `SIGSTOP` 信号把进程"冻结"了（不占 CPU、不丢状态），
  `SIGCONT` 即可原地续跑；这和第 5 步的"断点续跑"是两回事——前者进程还活着，
  后者是进程死了重启靠"跳过已有文件"续。
- **敲什么**：

  ```bash
  pkill -CONT -f serial_runner; pkill -CONT -f gen_image_lighting
  sleep 3; ps -o pid,stat,cmd -p $(pgrep -f gen_image_lighting | head -1)
  tail -1 log_0814.txt
  ```

- **成功标志**：ps 的 STAT 从 `T`（暂停）变回 `S`/`Sl`（运行）；过一两分钟再
  `tail -1 log_0814.txt`，完成数在涨（暂停时冻结在 2367/5097）。

## 第 7 步 失败补跑（出图 100% 后做）

- **原理**：部分任务会被平台安全审核拦截（日志里 `[FAIL] blocked_by_moderation`，
  多为人像误判），这类失败**有随机性，重试一轮能救回一部分**。
  思路：从日志抓失败行 id → 从清单把对应行抽出来存成补跑清单 → 再跑一次
  （已成功的行因为文件已存在会自动跳过，所以直接全量重跑同一命令也行，只是慢些）。
- **敲什么**（最简单做法——直接重跑同一命令吃"自动跳过"）：

  ```bash
  grep -c "\[FAIL\]" log_0814.txt     # 先看失败量
  nohup python3 -u gen_image_lighting.py --batch 0814 \
    --input-jsonl batches/0814/Prompt_with_images.4dedup.jsonl > log_0814_retry.txt 2>&1 &
  ```

- **成功标志**：retry 日志里大部分行"跳过"，只重跑失败行；两轮后仍失败的
  记下来单独汇报（多半是泳装等人像图被稳定拦截，需人工决定剔除或换途径）。
- **参考量**：0815 批有 113/855 行被拦（约 30 张图三轮全挂）。

## 第 8 步 几何对齐

- **原理**：生成模型重画整图时会有轻微缩放/平移，对齐脚本用特征点配准把生成图
  对回原图坐标（crop 或标记 unaligned），保证交付图和原图逐像素可比。
  **必须换 Python**：系统 python3 是 3.6，太旧跑不了对齐脚本。
- **敲什么**（每批一条）：

  ```bash

    --csv prod_work/Prompt_with_images_0815.csv --workers 4
  /root/miniconda3/envs/comfyui-v4.0/bin/python -u skills/lighting-destyle-align/align_batch.py \
    --csv prod_work/Prompt_with_images_0814.csv --workers 4
  ```

- **成功标志**：打印 `完成 ok=… crop=… unaligned=…`，生成
  `prod_work/Prompt_with_images_<id>_align_out/`（含 processed/、review/index.html）。

## 第 9 步 交付 CSV + 校验

- **原理**：把"原图路径、生成图路径、提示词、对齐结果"汇总成标注平台要的表，

- **敲什么**：

  ```bash

  python3 -u make_lighting_delivery_csv.py --batch 0814 --verify
  ```

- **成功标志**：写出 `batches/<id>/<id>_光影_final.csv`，verify 打印
  `路径检查 缺 0`、`id 重复 0`、`结论：通过`。

## 常见坑速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 出图结束报 `cancel_futures` TypeError | Python3.6 无害收尾错误 | 忽略 |
| 对齐报 `SyntaxError: future feature annotations` | 用了系统 python3 | 换 comfyui-v4.0 的 python |
| 出图全部"跳过" | work_dir 里已有同名产物 | 正常（续跑机制）；要重跑先清对应文件 |
| 清单 0 行 | config 里 image_root 路径不对 | ls 逐级核对 |
| `[FAIL] blocked_by_moderation` | 平台安全审核误拦 | 第 7 步重试；稳定拦的单独记录 |
| 大目录 find/du 前 | Ceph 共享存储 | 先 `getfattr -n ceph.dir.rfiles <目录>` 看文件数，>100 万停下确认 |
| 他人目录/网盘 | 只读红线 | 只能复制到自己工作区再改 |
